fix(player): stop swipes and sideways slides acting during the opening (issue https://github.com/N-Zik-Group/N-Zik/issues/818) (issue https://github.com/N-Zik-Group/N-Zik/issues/816)
  - Holding the finger down after a swipe action left the mini-player displaced: once the action ran, the swipe gestures are cut (`SwipeActionLatch.isFired`, now an observable state, drives `SwipeToDismissBox.gesturesEnabled` in `MiniPlayer.kt`, legacy, minimal edit) and a `LaunchedEffect` calls `dismissState.reset()` so the interrupted drag settles the box back to its position
  - Slow diagonal open triggering the swipe action: the swipe's touch slop is doubled (`WithDoubledTouchSlop.kt`, new, same doubling as the song rows) so the vertical open gesture wins, and the swipe is off as soon as the sheet leaves its original position (`isMiniPlayerSwipeEnabled`: `progress == 0f` and no action just ran)
  - Cutting those horizontal gestures left nothing to absorb sideways movement, and the sheet's `detectVerticalDragGestures` grabbed it and opened or closed the player: `CustomBottomSheet.kt` now uses `detectMostlyVerticalDragGestures` (`DominantVerticalDrag.kt`, new) — a mostly horizontal movement is neither consumed nor followed
  - The "mostly vertical" check was one-shot, at the touch slop: stopping mid-opening (finger down) then sliding sideways still moved the sheet through the slide's vertical drift, and the release fling used the vertical velocity. `OngoingDragDirectionMonitor` rechecks the direction continuously, every touch slop of accumulated movement (tumbling window); once it turns horizontal the drag stops following and the sheet settles with a zero velocity on release (`onDragEnd(aborted)` in `CustomBottomSheet.kt`)
  - The player's skip swipes (`Player.kt`, legacy, minimal edit) are off until the sheet is completely open: `disablePlayerHorizontalSwipe` is now derived from the preference AND `isExpanded` (`isPlayerHorizontalSwipeEnabled`), covering the 6 gestures that read it
  - A 45-degree slide still counts as vertical, at the start of the gesture and mid-gesture
  - Tests (44 in 7 classes, all green): DominantVerticalDragTest (6), OngoingDragDirectionMonitorTest (5), MiniPlayerSwipeActionTest (8), SwipeActionLatchTest (6), CustomBottomSheetTranslationTest (8), CustomBottomSheetThresholdTest (6), PlayerSheetStateAnchorTest (5); `:ComposeN-Zik:assembleDebug` OK. Device-verified by the maintainer across the rounds; the mid-gesture recheck itself was not re-verified on a device

fix(player): the mini-player no longer disappears on rotation or after a UI change
  - Root cause 1, `PlayerSheetState.kt` (legacy, minimal edit): the sheet state is rebuilt from its last anchor whenever its bounds change (rotation, insets), but the anchor was only updated by `expand`/`collapse`/`dismiss`, never by `snapTo`, which is what start-up and media transitions use. The rebuilt sheet came back "dismissed" and `CustomBottomSheet` hid the mini-player. `snapTo` and `snapToAndWait` now remember the anchor matching the value (values between two anchors keep the last one)
  - Root cause 2, `MainActivity.kt`: about fifteen UI preferences (nav bar position and type, UI type, mini-player type, ...) call `recreate()`. The player service is not bound yet on the new instance, so the current media reads as absent and the sheet is dismissed, and nothing presented it again once the media came back (`isPlayerInitialized` is saved as true). The media effect is now also keyed on the sheet and calls the new `showMiniplayerIfDismissed()` (`MiniPlayerAutoExpand.kt`) when media is present
  - Tests: PlayerSheetStateAnchorTest (5: anchor remembered for collapsed / expanded / dismissed, kept between anchors, `snapToAndWait`), MiniPlayerRestoreTest (2: a dismissed sheet is brought back collapsed, a showing sheet is left untouched)

  - Placement, new `MiniPlayerTopAnchor.kt`: below the app header (64dp + status bar) with an 8dp gap, and below the top nav bar when it is at the top too (`miniPlayerTopInset`). It leaves with the header on scroll-hide (`miniPlayerTopPaddingPx`), fully above the screen once the header is gone

  - Content: `Skeleton.kt` (legacy) reserves the room under a top mini-player (mini-player height + gaps), shrinking with the scroll-hide (`miniPlayerContentReservePx`) and eased over 250ms when the mini-player appears or leaves, so the list no longer pops

fix(player): mini-player swipe actions run once per gesture and act on the current song (issue https://github.com/N-Zik-Group/N-Zik/issues/818) (issue https://github.com/N-Zik-Group/N-Zik/issues/816)
  - #818, repeated action: once the finger reaches the end anchor, `AnchoredDraggableState` evaluates the veto of `confirmValueChange` again on every drag delta, and `MiniPlayer.kt` ran the action inside that callback. The new `SwipeActionLatch` lets the action run once per gesture and is rearmed when the swipe box is back at rest (`requireOffset()` back to 0)
  - #816, like on the wrong song: `rememberSwipeToDismissBoxState` keeps the `confirmValueChange` it got at the first composition, so the swipe used the state of that first composition. The right swipe now reads `binder.player.currentMediaItem` when the swipe happens instead of a composition value, and the sheet state, mini-player type, binder and context go through `rememberUpdatedState`
  - Return to position: the action changes the content (new title, like icon), which recomputes the swipe anchors, and the state could settle in a dismissed direction and stay displaced with its gestures off. A `LaunchedEffect` now calls `dismissState.reset()` as soon as `settledValue` is no longer `Settled`
  - Action choice moved to the pure `miniPlayerSwipeAction` (`MiniPlayerSwipeAction.kt`): right swipe likes on the Essential type and goes back on the others, left swipe skips to the next song. The haptic feedback now only fires when an action really runs
  - `MiniPlayer.kt` is a legacy file (minimal edit). `SwipeableContent.kt` (song items) is untouched: it keeps the same deprecated `confirmValueChange` scheme, without the repetition in practice since a song row is never swiped to its far end
  - Tests (9 in 2 classes): SwipeActionLatchTest (5: first call fires, later calls of a gesture do not, 200 calls run the action once, release rearms, release of an unused latch), MiniPlayerSwipeActionTest (4: right swipe on Essential and on the other types, left swipe, no action at rest)
  - Verification: both classes green, and the main sources compile through `:ComposeN-Zik:testDebugUnitTest`. Checked on a device by the maintainer. NOT re-run: the full `testDebugUnitTest` suite and a separate `assembleDebug`. NOT covered by a test (no Compose harness in the module): the drag behavior itself, the reset after the action, the like on the current song.
