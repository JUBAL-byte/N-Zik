fix(player): the mini-player no longer disappears on rotation or after a UI change
  - Root cause 1, `PlayerSheetState.kt` (legacy, minimal edit): the sheet state is rebuilt from its last anchor whenever its bounds change (rotation, insets), but the anchor was only updated by `expand`/`collapse`/`dismiss`, never by `snapTo`, which is what start-up and media transitions use. The rebuilt sheet came back "dismissed" and `CustomBottomSheet` hid the mini-player. `snapTo` and `snapToAndWait` now remember the anchor matching the value (values between two anchors keep the last one)
  - Root cause 2, `MainActivity.kt`: about fifteen UI preferences (nav bar position and type, UI type, mini-player type, ...) call `recreate()`. The player service is not bound yet on the new instance, so the current media reads as absent and the sheet is dismissed, and nothing presented it again once the media came back (`isPlayerInitialized` is saved as true). The media effect is now also keyed on the sheet and calls the new `showMiniplayerIfDismissed()` (`MiniPlayerAutoExpand.kt`) when media is present
  - Tests: PlayerSheetStateAnchorTest (5: anchor remembered for collapsed / expanded / dismissed, kept between anchors, `snapToAndWait`), MiniPlayerRestoreTest (2: a dismissed sheet is brought back collapsed, a showing sheet is left untouched)

fix(player): honour the "top" mini-player position and adapt the layout to it
  - Root cause, `CustomBottomSheet.kt`: the sheet box always pushed itself to the bottom (`translationY = targetY * (1 - p)`), which cancelled the `TopCenter` alignment set in `MainActivity.kt`. The translation is now the pure `sheetTranslationY`, with a new `topPadding` provider (read at draw time) that anchors the mini-player at the top; the bottom behavior is unchanged
  - Placement, new `MiniPlayerTopAnchor.kt`: below the app header (64dp + status bar) with an 8dp gap, and below the top nav bar when it is at the top too (`miniPlayerTopInset`). It leaves with the header on scroll-hide (`miniPlayerTopPaddingPx`), fully above the screen once the header is gone
  - Gestures: mirrored when anchored at the top (`sheetDragDelta`, `sheetFlingVelocity`): swipe down opens the player, swipe up closes it
  - Side rails: with the nav bar on the left or right the collapsed mini-player narrows on that side (`collapsedStartInset` / `collapsedEndInset`, `miniPlayerSideInset`, `computeCardGeometry` now takes per-side insets) and its tap target no longer covers the rail; it still deploys to full width
  - Content: `Skeleton.kt` (legacy) reserves the room under a top mini-player (mini-player height + gaps), shrinking with the scroll-hide (`miniPlayerContentReservePx`) and eased over 250ms when the mini-player appears or leaves, so the list no longer pops
  - Nav bar at the top: it now leaves with the header instead of staying under the status bar (`AppNavigation.kt`, legacy: the content can go up by the bar's height; the scroll-hide travel in `MainActivity.kt` includes it). With a rail on a side the content stays clear of the status bar so the rail buttons remain reachable. `HorizontalNavigationBar.kt` (legacy): no rounded top corners for a top bar
  - Tests (33 in 6 classes): PlayerSheetStateAnchorTest and MiniPlayerRestoreTest above, CustomBottomSheetTranslationTest (8), CardGeometryInsetsTest (6), MiniPlayerTopAnchorTest (8), MiniPlayerContentReserveTest (4)
  - Verification: `:ComposeN-Zik:testDebugUnitTest --tests "app.n_zik.android.components.*"` green (the whole package, no skipped test). Checked on a device by the maintainer while iterating on the behaviors above. NOT re-run after the last edits: the full `testDebugUnitTest` suite and a final `assembleDebug`. NOT covered by a test (no Compose harness in the module): the real sheet rebuild on rotation, the `recreate()` flow, the scroll-hide travel of the nav bars, the eased content reserve. The height of the top nav bar (`TOP_NAV_BAR_HEIGHT`) is derived from `HorizontalNavigationBar`, not measured: it will drift if that bar changes
